# geo-monitor-audit

在 19 家 GEO 监测产品的公开材料上逐字段统计后，**9 个关键字段没有任何一家公开**：
每 prompt 采样次数、噪声地板、置信区间、模型版本锁定、席位定价、历史数据可迁移性、
合同锁定条款、主体工商可核实性、团队公开信息。

这意味着：**厂商给你的「效果提升 X%」，你无法从公开材料判断它是否超过自然波动。**

```bash
npx geo-monitor-audit disclosure   # 逐字段披露率矩阵
npx geo-monitor-audit verify       # 校验每份证据快照的 sha256 与来源完整性
npx geo-monitor-audit score        # 列出各产品由字段重算得到的分数
```

19 份证据化档案随包分发，装完无需克隆仓库即可运行。

## 几个数出来的结论

**入门档的标价不可直接比较。** Profound 入门档是 1 个引擎 × 50 个 prompt，另一家是
8 个引擎 × 1 个 prompt——月费同一量级，买到的东西完全不同。可比的单位是
「引擎数 × prompt 数 × 每月采样次数」，这三项的披露率分别是 32%、26%、**0%**。

**标价大多公开，成本却算不出来。** 定价页 15/19 公开（79%），但席位定价 0/19、
退款条款 1/19、单位通胀风险 1/19，10/19 只接受年付。

**平台覆盖 ≠ 终端覆盖。** 写「支持豆包」不能推定同时覆盖 browser/web、桌面客户端、
iOS App、Android App、小程序和 API。19 家里没有一家公开完整的逐引擎 × 逐终端矩阵。

## 采购前必须现场问出来的五个数

公开材料答不了下面任何一条：

1. 每个 prompt 每个终端每次采集重复几次？
2. 月费包含几个席位，第 6 个人多少钱？
3. 问题集从 30 条扩到 100 条，计价单位是否跳档？
4. 移动端和 PC 端是否分别计费？
5. 合同期内历史数据能否导出、终止后能否带走？

## 为什么这些数字可以被质疑

数据不是写在文章里的结论，是从 19 份 JSON 档案算出来的：

- **模型在物理上无法编造来源 URL**——网络请求全部由 Python 完成，模型只能读已落盘的证据文件
- **分数由代码从字段重算**，模型无法给偏爱的产品抬分。改任一档案的分数，`score` 会报错并打印差异
- **每份证据快照带 SHA-256**，篡改任一快照，`verify` 立即失败
- 本包的 JS 实现与仓库内的 Python 实现**互为交叉校验**，`node test.js` 断言两者输出逐字节一致

127 个离线测试 + 5 道 CI 门。

## 利益披露

本报告作者与其中一家产品（透镜GEO）存在业务关联。报告对它同样标注了能力空白
（企业级 API 未公开），并在它不擅长的场景里把竞品放在第一位。
**请用报告中的独立抽检方法验证任何结论，包括关于透镜GEO的结论。**
